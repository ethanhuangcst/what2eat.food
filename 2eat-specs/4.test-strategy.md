## 1. Stricter deltas vs common-test-strategy

| Delta | Rule |
| --- | --- |
| Thin client | Decide, details, map links, and chat **must** reach places-agent over HTTP from the BFF. Browser never holds caller key, map-vendor keys, or LLM keys. |
| No invented restaurants | Decide/tests must fail if the BFF returns canned restaurant names when places-agent returned empty or failed. |
| Live honesty (ADR-021) | MVP-2+ DoD: restaurant cards come from **live** places-agent (`PLACES_VENDOR_MODE=live`). No `fixture_` native ids in MVP sign-off. |
| Chat history | List and place chat transcripts live in **browser-local storage only**. Contract tests assert **no** chat rows in the app DB; E2E verifies restore + clear on logout. |
| Chat transport | BFF calls `POST /v1/chat` on places-agent (HTTP-only per ADR-020). Browser does not call MCP. |
| Four locales | Consumer UI: `EN`, `CN`, `HK`, `TW`. HK ≠ TW on pinned keys. Tests use keys / `data-testid` / role — not English-only copy. |
| Two trust modes | **User session** (cookie) for what2eat pages/API. **Caller API key** only on BFF → places-agent server-to-server. Session must not call places-agent directly from the browser. |
| Secrets | Caller key, `OPENAI_*`, map-vendor keys, session secret must not appear in browser storage, client JSON, Playwright HAR, or screenshots. |
| Auth forms | Token-in-email flows (reset/set password): one POST JSON path; E2E asserts credentials never appear in URL (lessons §1). |
| Default PR CI | Unit + BFF contract with **injected** places-agent HTTP (fast, deterministic). **Not** sufficient for MVP-2/3 DoD alone. |
| MVP E2E sign-off | **Real** what2eat process + **real** places-agent (live vendors) + isolated test DB. **No** fixture/mock/fake restaurant payloads for MVP completion. |

The common quality checklist still applies in full. Extra items are in §11.

### 1.1 Fixture vs live — two lanes (do not confuse them)

Learned from places-agent MVP-1: green fixture CI masked live lies ([ADR-021](../../workspace-specs/adr/ADR-021-live-vendor-no-fixture.md)).

| Lane | Purpose | Restaurant data | Blocks merge? |
| --- | --- | --- | --- |
| **Fast CI** | Unit, BFF contract, auth, i18n, preference-match math | Injected places-agent responses or recorded JSON | Yes — every PR |
| **MVP DoD / live probe** | Prove the thin client works against real vendors | Live places-agent + live keys | Yes — before MVP-2/3 close |

**Anti-pattern:** Mark Decide “done” because fast CI passed with stubbed `search_restaurants` JSON. That is `fixture-only`, not MVP DoD.

### 1.2 MVP DoD — live stack (binding)

An MVP that touches place data (**MVP-2**, **MVP-3**) is **done** only when **all** are true:

1. **Real stack:** what2eat app + places-agent both running; BFF uses a real caller API key from env.
2. **Live vendors:** places-agent `PLACES_VENDOR_MODE=live` for the probe pin(s) used in sign-off.
3. **No fixture ids:** Decide cards in the probe have vendor `native_id` values that do **not** start with `fixture_`.
4. **Operator pin:** At least one documented probe location per supported region (e.g. EN: Clerkenwell + `GOOGLE_MAPS`; CN: Hangzhou + `AMAP`) — attached to the MVP retrospective.
5. **Playwright MVP journey** green against the live stack (§7).
6. **User confirmation:** “Do you confirm this MVP is usable?” per workspace DoD.
7. **Status label:** `live-honest` or `fail-closed` — not `implemented` or `fixture-only` for place-data features.

MVP-1 (account/profile only) does not call places-agent but still requires real DB, real session auth, and real email transport (Resend sandbox or dev outbox — not a UI-only fake success).

### 1.3 Honesty matrix (what2eat layer)

Update when a live probe last passed:

| Path | Live dependency | Fast CI | Live probe | MVP |
| --- | --- | --- | --- | --- |
| Register / login / profile | App DB + session | Vitest + Playwright | Real sign-in path | MVP-1 |

## 3. Pyramid (this product)

Target mix ~70 / 20 / 10.

| Layer | What to put here | Typical tools |
| --- | --- | --- |
| Unit / component (~70%) | Preference-match scoring, pagination/reshuffle logic, i18n catalog lookup, chat localStorage keys, Zod schemas, map deeplink picker | Vitest (or project test runner) |
| Integration / contract (~20%) | `/api/*` BFF routes with injected places-agent fetch; session auth; DB CRUD for profile/saved/history; chat route does not INSERT transcript | Vitest + test DB |
| E2E (~10%) | One **complete MVP journey** per slice in real Chromium | Python Playwright + live stack |

Do **not** assert Decide solely through unit tests with hard-coded restaurant arrays.

## 4. Mapping AC → tests (TDD)

1. Pick **one** user story from [`3.2eat-stories.md`](./3.2eat-stories.md) (incremental delivery).
2. For each AC in Part 2:
   - **Red** — test states the Then (observable outcome, keys, DB state, localStorage).
   - **Green** — minimal implementation.
   - **Refactor** — stay green.
3. Name tests `should_[expected]_when_[condition]`.
4. One behavior per test; AAA; order-independent.

| Story area | Primary layer | Live required for DoD? |
| --- | --- | --- |
| Shell, home, i18n, family footer | Component + Playwright | MVP-1: real app only |
| Account, profile | Integration + Playwright | MVP-1: real DB |
| Decide, place, saved | Unit (match logic) + integration (BFF) + Playwright | MVP-2: **yes** |
| Chat | Integration + Playwright (localStorage + no DB) | MVP-3: **yes** |
| History | Integration + Playwright | MVP-3: real DB + live Decide prerequisite |

## 5. Unit and component

Cover at least:

- Preference match: strong / partial / weak from profile + Decide context (no LLM).
- Short-list pagination and reshuffle cursor (deterministic given a fixed search result set in **unit** tests only).
- Fit-reason string keys composed from profile fields (not hard-coded English in components).
- Map deeplink selection from `sources[]` (client env policy; no secrets in URL).
- i18n: locale → catalog; HK vs TW differ on pinned keys; fallback EN → key.
- Family footer: current product is not an `<a>`; siblings have `target="_blank"`; public vs app chrome classes; computed font-size of footer row stays 12px under EN and CN (locale smoke).
- Chat storage: list scope vs place scope keys; clear on logout; cap/max messages if implemented.
- Auth: password hash verify, token expiry, session cookie name isolated from places-agent admin.

**Mocks allowed (fast CI only):** clock, injected `fetch` to places-agent, Resend transport when no sandbox key.

**Not allowed for MVP DoD:** BFF Decide handler that returns a static restaurant list without calling places-agent in production code.

## 6. Integration / contract

### 6.1 App BFF (`/api/*`)

- Session required for Decide, profile mutations, saved, history; public routes for home, login, register, reset.
- Mutating routes: CSRF / Origin check (same pattern as places-agent admin lessons).
- Decide POST: forwards geocode + `search_restaurants` to places-agent; response includes `sources[]`, skip reasons, last-updated.
- Details GET: `get_place_details` for vendor native id from card.
- Chat POST: forwards to places-agent `POST /v1/chat` with scoped context; **does not** persist messages.
- After chat POST: assert DB has **zero** rows in any `chat_*` table (or equivalent).

### 6.2 places-agent client module

- Uses `Authorization: Bearer` caller key from server env only.
- Parses envelope `{ agent: "places-agent", ... }`.
- Surfaces provider skip keys to UI (`errors.provider_failed`).
- Optional Tripadvisor enrich via HTTP search body only (ADR-020).

### 6.3 Injected HTTP in default CI

- Replace places-agent `fetch` with fixtures for speed.
- Fixtures must mirror **real** card shape from [`1.places-agent`](../../1.places-agent) — not a simplified fake schema.
- Tests must include a **fail-closed** case: agent returns empty → BFF returns empty state key, not invented cards.

### 6.4 Email

- Reset/set password: Resend sandbox or dev outbox (`getMailOutbox()` pattern from places-agent).
- E2E may read outbox in test env; production uses real Resend.

## 7. E2E — consumer web (Playwright)

what2eat is a **dynamic** Next.js app. Start the **real** server(s), then automate.

### Harness

1. Run `python scripts/with_server.py --help` (add when repo scaffold exists) before inventing a runner.
2. **MVP-1:** one server — what2eat (+ migrate/seed test DB).
3. **MVP-2/3:** two servers — what2eat + places-agent (`PLACES_VENDOR_MODE=live`, real keys in operator `.env.local` — not committed).
4. Python `playwright.sync_api`, Chromium `headless=True`.
5. Prefer `data-testid` and roles over visible English (i18n).
6. `domcontentloaded` + explicit test-id wait (HMR makes `networkidle` flaky on dev).
7. Clear session before login journeys (`/login/fresh` or equivalent).
8. Desktop + one mobile width per changed screen.
9. Close browser when done.

### Critical journeys (minimum)

| Journey | MVP | Covers |
| --- | --- | --- |
| Home → register → profile (personal + tastes) → logout → login → profile persisted | **MVP-1** | Features 7–13, 1–6; no URL credential leak on register; family footer present on home + app |
| Locale EN → HK on home (copy + footer mark size unchanged) | **MVP-1** | i18n-01 + footer-02 AC3 |
| Sign in → Decide (real pin) → cards with vendor source ids → Details → Why → Save → Saved → Unsave | **MVP-2** | Features 14–19, 21–22, 24–26; **live** cards |
| Reshuffle + pagination on live list | **MVP-2** | decide-03, decide-04 |
| Open map from card (popup or new tab) — URL has no API key | **MVP-2** | decide-05, place-04 |
| Decide → list chat (real reply) → refresh → transcript in localStorage → logout clears chat | **MVP-3** | decide-07 |
| Details → place chat → separate from list transcript | **MVP-3** | place-03 |
| Decide + save → History row → re-run Decide link | **MVP-3** | history-01 |

**Empty / failure paths (at least one per MVP where applicable):**

- MVP-1: failed login message.
- MVP-2: empty Decide (impossibly tight filters) **or** partial vendor banner when one provider skipped — use live stack behavior, not mocked banner injection in E2E.
- MVP-3: history empty state before first Decide.

## 8. i18n

- Tests assert **keys**, `data-testid`, or role — not a single language’s sentence.
- At least one path resolves default `EN`; smoke `EN` → `HK`.
- HK vs TW: unit fixture proves different strings on pinned keys.
- Protocol ids (`AMAP`, `GOOGLE_MAPS`, `TRIPADVISOR`, `places-agent`) stay literal in assertions.
- Vendor place **names** in E2E come from live vendor (Layer B) — do not assert mock-up sample names like “St. JOHN” in live probes unless that name truly appears for the probe pin.

## 11. Quality checklist (extras)

Meet **all applicable** common-test-strategy items, plus:

- [ ] Token forms: E2E submit + URL never contains `password=`
- [ ] User session cannot call places-agent `/v1/*` directly from browser
- [ ] Caller key never in client bundle, localStorage, or sessionStorage

- [ ] Logout clears list and place chat keys
- [ ] MVP-2 live probe: no `fixture_` native ids on cards

- [ ] MVP DoD used real stack — not mock-up HTML (`ui-mockup/`) as product proof

## 13. Failure handling

Fix production code or a wrong test. Do not delete or skip a failing AC test to go green. Do not lower coverage or drop live probes to pass MVP DoD.

**Anti-patterns (from places-agent lessons — do not repeat):**

- Ship Decide with hard-coded restaurant cards “until agent is wired.”
- Mark MVP-2 done after unit tests only.
- Use `ui-mockup/` static HTML as E2E substitute for the Next app.
- Persist chat in DB “for convenience.”
- Treat `make test` fixture green as live vendor honesty.
- Verify auth with `curl` only — no Playwright submit + URL assert.

## 14. Traceability to places-agent

what2eat relies on places-agent capabilities already covered by agent HTTP tests (TC-H01–H15). Before MVP-2 DoD:

- places-agent MVP-1 restaurant search path must be **`live-honest`** for the vendors what2eat will call.
- what2eat BFF must not re-implement vendor adapters.
- Regression in places-agent live probes blocks MVP-2 sign-off even if what2eat unit tests pass.
