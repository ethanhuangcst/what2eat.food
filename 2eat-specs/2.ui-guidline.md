# What2Eat — UI guideline

Pixel and interaction contract for **what2eat.food**. Requirements: [`1.req-specs.md`](./1.req-specs.md). Clickable mock-ups: [`ui-mockup/`](./ui-mockup/). Per-screen layout (DOM, classes, measurements, test ids): [`7.page-by-page-UI-design.md`](./7.page-by-page-UI-design.md). Family architecture: [`../../workspace-specs/2.architecture.md`](../../workspace-specs/2.architecture.md).

This document covers **consumer** screens only. places-agent operator chrome is out of scope.

Filename keeps the requested `guidline` spelling so links stay stable.

---

## 1. Subject

| | |
| --- | --- |
| **Product** | Restaurant picker for people who cannot decide what to eat |
| **Audience** | Hungry individuals and small groups (weeknight dinner, office lunch, mixed diets) |
| **Job of the UI** | Get a **short** ranked list from location + meal + preferences, show **why** each place fits, and let the person open a map or ask a follow-up — without pretending the app is a menu, allergen label, or booking system |

The characteristic moment is not a dashboard metric. It is the pause at the table: three options on placemats, steam still rising, a decision that can stay small.

---

## 2. Direction

**Picnic cloth and steam bowl.** Happy and relaxing: the calm after sitting down, not a delivery sprint and not spa-wellness mint blobs.

Personality sits in **one** place: a **soft gingham field** plus a **fried-egg mark with steam**. Cards read as placemats. Everything else stays quiet — no numbered 01/02/03 markers, no hairline broadsheet, no black + acid-green operator look.

| Do | Do not |
| --- | --- |
| Generous radius (bowl rim / placemat), dual-tone cloth, citrus only on the primary action | places-agent tokens (`#fafafa`, radius 0, uppercase mono eyebrows as the whole personality) |
| Fit and readiness as **text labels** plus a calm chip | Color-only traffic lights |
| Short list (about 3–5 cards), reshuffle in place | Infinite feed, map vendor chrome in the browser |
| Locale switcher `EN CN HK TW` on every shell | A two-way 中文 / EN switcher |
| Empty and error states that say what to change | Vague apologies, blank screens |

places-agent admin stays 性冷淡 on purpose. Copying that look here would make a consumer dinner picker feel like a key-issuing console.

**Aesthetic risk (justified):** a visible picnic gingham instead of a flat cream canvas. Deciding what to eat is a tablecloth problem, not a document problem. Surrounding UI stays still so the cloth and steam are the only memorable devices.

**Rejected defaults (frontend-design):** (1) cream `#F4F1EA` + terracotta serif, (2) near-black + acid green, (3) broadsheet / zero radius. This product uses peach-rice + celadon glaze + rounded Fredoka wordmark — none of those three.

CJK face is **獅尾腿圓 (Swei Gothic Leg)**. `CN` uses **獅尾腿圓簡體** (`CJK SC`). `HK` and `TW` use **獅尾腿圓繁體** (`CJK TC`) — not the SC file. `logo-word` stays Fredoka. CJK headings use tracking `0`.

**Custom CJK webfont (mock-up and product)**

Google Fonts `@import` only covers their catalog. For a face you pick (獅尾腿圓, a licensed file in `assets/fonts/`, etc.):

1. Host a `woff2` (self-host under `assets/fonts/` or a CORS-open CDN).
2. Declare `@font-face` with `font-family`, `font-weight`, `font-display: swap`, and `src: url(...) format("woff2")`.
3. Point `--font-ui` / `--font-display` at that family. Keep Latin (Fredoka / Figtree) first on the wordmark.
4. Use **separate files for SC and TC** when the foundry ships both — do not one-file “translate” 简繁.
5. Prefer one Regular file per script in the mock-up (~6MB CJK). Extra weights double the download.

Current mock-up families: `獅尾腿圓簡體` (CN) and `獅尾腿圓繁體` (HK/TW), Regular, version `2.129`. `@font-face` tries `local("獅尾腿圓體TC")` first, then the jsDelivr woff2.

1. `eat.nav.decide` → decide now (landing after login)
2. `eat.nav.profile` → preference profile
3. `eat.nav.saved` → favorites
4. History is reached from saved (`eat.nav.history`), not a fourth top-level item (keeps the bar quiet)

## 6. Components

### 6.1 Header (app)

- Left: mark + `what2eat.food` (links to decide when signed in, home when not)
- Center/left-of-actions: Decide, Profile, Saved — underline + weight for the active item (not a colored pill farm)
- Right: `eat.header.hello` with `{name}`, circular avatar (**profile photo** when uploaded, otherwise initials), then **`.app-user__tools`** — locale switcher (fixed 10.5rem, four equal segments) + Logout (fixed min-width 5.75rem). Greeting and Logout use the **same 0.875rem type size** in EN/CN/HK/TW.
- Mobile: locale + avatar stay; nav collapses behind `eat.nav.menu` (same labels, no icon-only)

### 6.2 Buttons

| Kind | Use |
| --- | --- |
| Primary | Glaze fill, rice text, radius `--radius-control`. Decide, save, send. |
| Quiet | Plate fill, glaze border. Reshuffle, secondary. |
| Danger | Outline `--danger`. Unsave / delete with a confirm dialog when the action is destructive. |
| Text | Ink underline on hover. Auth alternate actions. |

Height `--control-h`. Visible `:focus-visible` ring: 2px zest on glaze, offset 2px.

### 6.3 Fields

Label above control (sentence case). Helper under the field. **Field errors** use `role="alert"`, `eat.errors.*` keys, and the pattern in **§6.10**. Do not rely on red border alone.

Do not use browser-default invalid styling or autofill wash as the error signal — controls keep `--plate` fill; see **Form validation errors** below.

#### Form validation errors

Auth and profile forms must tell the person **which field** failed and **what to change**. Generic copy without a visible field state is forbidden.

#### Rules

| Rule | Detail |
| --- | --- |
| **Field-local first** | Put the message **directly under** the offending control in `.field-error`. One sentence: what is wrong + how to fix. |
| **Highlight contract** | If copy mentions “highlighted fields”, every cited problem **must** have `.field.is-invalid` on its `.field` wrapper. Otherwise do not use that phrase — name the field in the sentence instead. |
| **Background stays plate** | Invalid controls keep `background: var(--plate)`. Error state = **danger border** + field error text. Override `:-webkit-autofill` so autofill never looks like an app error (see CSS below). |
| **Form banner sparingly** | Use a top-of-form `.error` only for errors **not tied to one field** (network, CSRF, session). Field problems never use a form-level banner alone. |
| **Uniqueness** | **Email** is the only unique identifier for accounts. **Name may repeat** across users — never show “name already taken”. |
| **Retire generic validation** | Do not show `eat.errors.validation` (“Please check the highlighted fields”) to end users. Reserve for logs; map server codes to field keys in the UI. |

#### DOM pattern

```html
<div class="field is-invalid" data-field="email">
  <label for="email" class="is-required">Email</label>
  <input id="email" name="email" type="email" aria-invalid="true" aria-describedby="email-error" />
  <p class="field-error" id="email-error" role="alert" data-field-error="email">An account with this email already exists.</p>
</div>
```

- Wrapper: `.field.is-invalid`
- Message: `.field-error` (0.8125rem, `--danger`, margin 0)
- Control: `border-color: var(--danger)`, `aria-invalid="true"`, `aria-describedby` → error id
- Focus the **first** invalid field on submit

#### Register field error keys (MVP-1)

| Field | Key | When |
| --- | --- | --- |
| Name | `eat.errors.name_required` | Empty on submit |
| Email | `eat.errors.email_required` | Empty |
| Email | `eat.errors.email_invalid` | Bad format |
| Email | `eat.errors.email_taken` | Duplicate email (409) |
| Age | `eat.errors.age_out_of_range` | Provided value &lt; 13 or &gt; 120 (optional field — empty is valid) |
| Password | `eat.errors.password_required` | Empty |
| Password | `eat.errors.password_too_short` | Fewer than 8 characters |
| Confirm | `eat.errors.password_mismatch` | Does not match password |
| Photo | `eat.errors.photo_too_large` | Optional upload exceeds limit |

Form-level only: `eat.errors.csrf`, `eat.errors.network`, `eat.errors.session_expired`.

Login keeps a single form error (`eat.errors.login_failed`) — credentials are not split for security.

#### CSS (product + mock-up)

```css
.field.is-invalid input,
.field.is-invalid select,
.field.is-invalid textarea,
.field.is-invalid .password-field input,
.field.is-invalid .location-field input {
  border-color: var(--danger);
  background: var(--plate);
}

.field-error {
  color: var(--danger);
  font-size: 0.8125rem;
  line-height: 1.35;
  margin: 0;
}

/* Autofill must not mimic error or “highlighted” state */
.field input:-webkit-autofill,
.field input:-webkit-autofill:hover,
.field input:-webkit-autofill:focus {
  -webkit-box-shadow: 0 0 0 1000px var(--plate) inset;
  -webkit-text-fill-color: var(--ink);
  transition: background-color 9999s ease-out 0s;
}
```

Mock-up query previews: `02-register.html?error=email_taken`, `?error=password_short` — see [`7.page-by-page-UI-design.md`](./7.page-by-page-UI-design.md) §5 and §15.

#### Save confirmation (profile)

After **Save personal info** or **Save tastes**, show `.callout.is-info` **in that form’s action row**, directly above the submit button — never at page top where long forms hide it. Match keys `eat.profile.personal_saved` / `eat.profile.saved`; scroll the notice into view when it appears. Register/login do not use this pattern (register navigates to profile; login navigates to decide).

### 6.4 Option card (placemat)

Canonical anatomy, class names, and measurements: [`7.page-by-page-UI-design.md`](./7.page-by-page-UI-design.md) §1.7. The **current mock** shows name, rating, `sources[]`, vendor type, address, optional Tripadvisor line, **fit badge only**, distance/warnings, then Details / Map (or Unsave). Do not add cuisine tags, price band, or a readiness chip on the card unless the mock is updated.

Required on the **card** (matches the mock):

- Place name (vendor string — Layer B, do not glossary-rewrite)
- Rating or `eat.card.rating_missing`
- `sources[]` vendor ids (mono, untranslated)
- Vendor type string (`eat.card.category`)
- Address (clamp 2 lines); Tripadvisor review line only when enrich returned it
- Fit badge only (`eat.match.fit.strong` / `partial` / `weak`) — not a readiness chip
- Distance / ETA when present (mono, `Intl` in product), or `eat.card.unknown_distance`
- Alerts when they apply (closed, long travel, incomplete hours, price unavailable, weaker after refresh)
- Actions: Details + Map (Decide, Map only if a deeplink exists) or Details + Unsave (Saved)

Cuisine, hours, phone, and why-it-fits live in the **details dialog**, not on the card.

Click / Enter on the photo or Details opens the dialog. “Open map” uses a secret-free deeplink chosen by this app from `sources[]` — never a vendor key in the page.

### 6.5 Match classification

Never color-only.

| Dimension | Values (keys) | Chip wash |
| --- | --- | --- |
| Fit | `eat.match.fit.strong` / `partial` / `weak` | celadon / zest-tint / blossom-terracotta tint |
| Readiness | `eat.match.ready.open` / `uncertain` / `closed` | same three washes |

Each chip includes a short description nearby or in `title`/`aria-describedby` (`eat.match.fit.strong_hint`, etc.).

### 6.6 Decision alerts

Banner or inline callout on card and details. Keys under `eat.alert.*`. If a top pick is weaker after refresh, use `eat.alert.weaker_after_refresh` on that card — do not silently reorder without a note.

### 6.7 Details dialog

Address, hours, contact when present, review snippets only if enrich ran, match explanation, sources, last update, Save / Unsave, Open map. Why content lives in the same dialog.

### 6.8 Why this pick + chat (details dialog)

Why content and chat live **inside the place details dialog** — no separate Why page.

Composer label `eat.chat.placeholder`. Send is `eat.chat.send`. Distinguish in the transcript: place fact (`sources[]`), user preference, model suggestion (`eat.why.kind_*`). Confidence is a **sentence**, not a fake gauge (`eat.why.confidence`).

**Chat history:** List chat (Decide floating panel) and place chat (details dialog) transcripts are stored **only in browser-local storage** on this device. The BFF forwards each message for a reply but does **not** persist transcripts to the database. Separate storage keys per scope (list vs place). Clear chat history from browser-local storage on log out. Do not sync chat across devices via the account.

### 6.9 Empty / partial

Empty: steaming egg, reason key, one action (widen filters / change pin). Partial: remaining cards plus `eat.decide.partial_banner` when a requested vendor skipped (`errors.provider_failed`). One skip must not blank the page.

## 7. Motion

- Home / gallery / auth / app header: three celadon S-curves rise off the yolk (`.mark-steam`), staggered.
- Decide primary: the same three curves beside the headline.
- Card hover: translateY `-3px`, shadow slightly deeper. Keyboard focus does not require hover motion.
- Dialog: fade + 8px rise, `180ms`.
- `prefers-reduced-motion: reduce`: no steam loop, no card lift, instant dialog.

No ambient particle fields, no staggered 01/02/03 reveals.

## 8. Copy voice

Write from the hungry person’s side. Name controls by what they do.

| Good | Avoid |
| --- | --- |
| Find places | Submit query |
| Reshuffle | Regenerate recommendations |
| Save | Add to favorites store |
| Hours incomplete — check the restaurant | We sincerely apologize for the inconvenience |
| Nut allergy is what you entered. The restaurant did not confirm it. | Allergen-safe certified |

No hype labels (“perfect match!”, “you’ll love this”). Fit is strong / partial / weak.

Protocol ids stay English: `what2eat.food`, `AMAP`, `GOOGLE_MAPS`, `TRIPADVISOR`, `places-agent`, locale codes.

## 9. i18n

- All user-facing strings are keys. Mock-ups use `ui-mockup/assets/i18n.js` so `file://` works.
- Locales: `EN`, `CN` (`zh-CN`), `HK` (`zh-HK`), `TW` (`zh-TW`).
- HK and TW catalogs **must differ** (ADR-011). No OpenCC. HK chrome is 書面語 (您 / 請), not 口語.
- Missing key → `EN` → raw key. Never HK→TW.
- Tests and mock-up selectors: `data-testid` / role, not one language’s copy.
- Vendor place names and addresses are Layer B: show what the vendor returned; do not translate them in the client.
- Mock-up samples are **different sit-down restaurants per locale** (EN London, CN Hangzhou, HK Central, TW Taipei). Do not reuse a takeaway stall as a restaurant card.
- Switcher always shows `EN CN HK TW`.

## 10. Accessibility

- Skip link `eat.a11y.skip`
- Visible focus on every control
- Dialog: labelled title, Escape, outside click, initial focus on Close or title
- Contrast: ink on cloth and glaze-on-rice meet a readable floor; zest is never the only indicator
- Touch targets ≥ 44px on meal chips and card actions
- Avatar alt is empty when the greeting already names the person; otherwise `eat.header.avatar_alt`

## 11. Out of scope in this UI

- Map SDK, vendor keys, caller API key, Quanzil keys in the page
- places-agent admin (keys, invites)
- Orders, payments, itinerary (`plan_itinerary`)
- Presenting AI copy as restaurant policy or medical advice
