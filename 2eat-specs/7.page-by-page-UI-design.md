| Visual identity, tokens, voice | [`2.ui-guidline.md`](./2.ui-guidline.md) |

**How to use this document**

1. Palette, type, cloth, copy voice, and a11y floor live in [`2.ui-guidline.md`](./2.ui-guidline.md). Do not invent a second system.
2. This file is the **per-screen DOM, class, measurement, i18n, and test-id contract**.
3. If this file and the mock HTML/CSS disagree, **the mock HTML + `mockup.css` win**. Update this file.
4. Implementation must keep the **same DOM order**, **same CSS class names**, and **the same i18n keys**. Port `mockup.css` (or reproduce computed layout 1:1). Do not restyle “to look similar.”
5. All user-visible strings are keys. EN copy below is reference only.

**Not product routes:** `ui-mockup/index.html` (gallery). `10-why.html` (redirect stub). Do not ship either.

**Precedence vs the guideline:** [`2.ui-guidline.md`](./2.ui-guidline.md) §6.4 still mentions cuisine tags, price band, and a readiness chip on the option card. The **current mock pick-card does not** — fit badge only; cuisine lives in the details dialog. **Follow the mock.**

## 16. i18n implementation rules

- Catalogs: `EN` `CN` `HK` `TW` — HK ≠ TW (ADR-011).
- Attributes: `data-i18n`, `data-i18n-attr`, `data-i18n-vars` (`{name}` interpolation), `data-i18n-placeholder`, `data-i18n-href`, `data-i18n-value`, `data-i18n-title`.
- Document title: `{data-title-key}` + ` — what2eat.food`.
- Never translate: `AMAP`, `GOOGLE_MAPS`, `TRIPADVISOR`, `$`/`$$`/`$$$`, `what2eat.food`, locale codes, `places.family:` label, sister hostnames.
- Sample restaurants **change per locale** in the mock (`eat.sample.*`). Product shows vendor Layer B names, not these samples.
- Selectors in tests: `data-testid` / role / key — not English copy.
