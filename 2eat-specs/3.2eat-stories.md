## Personas

| Persona | Who | Value |
| --- | --- | --- |
| Undecided diner | Signed-in user | Get a short, honest restaurant list without menu research |
| New visitor | Public home visitor | Understand the product and create an account |
| Returning user | Signed-in user with saved profile | Re-run Decide with saved tastes and revisit favorites |

## Terms

| Term | Means | Not this |
| --- | --- | --- |
| **Place fact** | Name, address, rating, phone, hours, etc. from map vendors via places-agent | Preference-match copy or chat suggestions |
| **Preference match** | BFF labels (strong / partial / weak fit) and “why it fits” reasons from profile + Decide context | A separate ranking product or Quanzil score |
| **Short list** | Paginated picks from the latest search for the current criteria | The full vendor result set |
| **List chat** | Agent chat about the current Decide list and filters | Place-scoped chat inside details |
| **Place chat** | Agent chat about one restaurant inside the details dialog | The only way to search |
| **Chat history** | User and agent messages kept in browser-local storage on this device | Account data in the database; server-side transcript store |

## MVP plan

Three slices. Each MVP is a **complete, shippable feature set** with its own E2E sign-off. **MVP DoD forbids fixture, mock, or fake restaurant data** — use a real what2eat stack, real user DB, and (from MVP-2 onward) **places-agent in live vendor mode**. Details: [`4.test-strategy.md`](./4.test-strategy.md) §1.2, [`5.tech-design.md`](./5.tech-design.md) §12.

| Slice | Outcome | Features | E2E journey (summary) |
| --- | --- | --- | --- |
| **MVP-1** | Onboarding product: shell, home, account, profile | **1–13** | Visitor registers → saves profile → signs out/in → profile persists; locale EN→HK |
| **MVP-2** | Decide with real places: search, cards, details, save | **14–19, 21–22, 24–26** | Signed-in user runs Decide on a real pin → real vendor cards → details + why → save → Saved → unsave |
| **MVP-3** | Agent chat + history (chat history browser-local only) | **20, 23, 27** | List chat + place chat with real agent replies → transcripts survive refresh → cleared on logout → History |

**Build order:** MVP-1 → MVP-2 → MVP-3 (one user story to DoD at a time within each slice). Do not start MVP-2 until MVP-1 DoD passes; do not start MVP-3 until MVP-2 DoD passes.

**MVP-1 notes:** No places-agent dependency. Auth and profile use the real app DB and real session cookies. Email flows use Resend sandbox or dev outbox — not a fake “success” banner without a server path.

**MVP-2 notes:** BFF calls places-agent HTTP only ([ADR-020](../../workspace-specs/adr/ADR-020-http-only-chat-and-enrich.md)). DoD requires live probe: restaurant names/ids from vendors, **no `fixture_` native ids** ([ADR-021](../../workspace-specs/adr/ADR-021-live-vendor-no-fixture.md)). Chat deferred to MVP-3.

**MVP-3 notes:** Chat uses `POST /v1/chat` via BFF (HTTP-only). Transcripts in browser-local storage only — verified in E2E and contract tests (no DB rows).

Backlog is **features 1–27**. Dismiss / cool-off (hide a pick for a cooldown period) is **out of scope** — not a TBD slice.

# Part 2 — Story mapping

## 1. Header · `header-01` — App header & navigation

**User Story 1 — Navigate between main sections**

As a signed-in user, I want navigation between Decide, Profile, and Saved so I can move through the app without losing context.

- **AC1:** Given I am signed in, when I open any app page, then Decide, Profile, and Saved are available in the header navigation.
- **AC2:** Given I am on Decide, when the page loads, then Decide is indicated as the current section.
- **AC3:** Given I am on a narrow viewport, when I open the mobile menu, then the same navigation destinations are reachable.

---

## 2. Header · `header-02` — Signed-in user chrome

**User Story 1 — See who is signed in**

As a signed-in user, I want to see my name and avatar in the header so I know which account is active.

- **AC1:** Given I am signed in as Mei Chen, when I view an app page, then the greeting shows my display name.
- **AC2:** Given I uploaded a profile photo, when I view an app page, then the header avatar shows a circular photo thumbnail (not only initials).
- **AC3:** Given I am signed in, when I choose Log out, then my session ends and I return to the public home.

---

## 3. Header · `header-03` — Locale switcher (app)

**User Story 1 — Switch locale on app pages**

As a user, I want to switch language from the app header so labels match my preferred locale.

- **AC1:** Given I am on an app page, when I select HK, then user-visible strings render in Hong Kong Traditional Chinese where catalog entries exist.
- **AC2:** Given a string has no translation in the selected locale, when the page renders, then the app falls back without breaking the page.

---

## 4. Footer · `footer-01` — Family footer (app)

**User Story 1 — Family links on signed-in pages**

As a signed-in user, I want the places.family footer on Decide, Profile, Saved, and History so I can reach sibling products without leaving the app chrome.

- **AC1:** Given I am on Decide, Profile, Saved, or History, when the page loads, then the footer shows one row: `places.family:` · where2play.place (underlined, new tab) · what2eat.food (current, not a link, no underline) · places.agent-mate.ai (underlined, new tab) · copyright.
- **AC2:** Given the page has an app header, when the footer renders, then its bar fill and top border match the app header; product marks have transparent logos and no chip/highlight backgrounds.
- **AC3:** Given I switch EN → CN → HK → TW, when I view the footer, then Latin footer type stays the same size (Figtree/Fredoka at 12px — not CJK UI metrics).

---

## 5. Footer · `footer-02` — Family footer (public)

**User Story 1 — Discover sibling products on public pages**

As a visitor on home or auth pages, I want places.family links that sit on the same picnic cloth as the page so the footer does not look like a separate bar.

- **AC1:** Given I am on home, register, sign-in, reset, set-password, or the mock gallery, when the page loads, then the footer matches the same row contract as footer-01 (label with colon, logos, current mark, sibling new-tab links, copyright).
- **AC2:** Given the page has no app header, when the footer renders, then it uses the page background with no top border, no distinct footer fill, and no chip/highlight backgrounds behind logos or labels.
- **AC3:** Given I switch locale on a public page, when the footer renders, then mark size stays consistent with EN (same as footer-01 AC3).

---

## 6. i18n · `i18n-01` — Four-locale catalogs

**User Story 1 — Localized product copy**

As a user, I want the product in EN, CN, HK, or TW so the experience matches my language preference.

- **AC1:** Given the locale is TW, when I view register, Decide, or place details, then visible labels resolve through the locale catalog (not raw key names).
- **AC2:** Given HK and TW are both Traditional Chinese, when I switch between them, then wording differs where the catalogs differ (not a single shared Traditional file).
- **AC3:** Given protocol ids such as AMAP or GOOGLE_MAPS appear, when the locale changes, then those ids stay untranslated.

**User Story 2 — Locale on public pages**

As a visitor, I want a locale switcher on public pages so I can read home and auth flows in my language.

- **AC1:** Given I am on the public home or an auth page, when I change locale, then the page copy updates without signing in.

---

## 7. Home · `home-01` — Public landing

**User Story 1 — Understand the product**

As a visitor, I want a clear landing page so I know what what2eat does before creating an account.

- **AC1:** Given I open the public home, when the page loads, then I see a headline, supporting lead copy, and preview cards illustrating restaurant picks.
- **AC2:** Given I am not signed in, when I choose Find places, then I am taken to register.
- **AC3:** Given I already have an account, when I choose Sign in, then I am taken to the sign-in flow.

---

## 8. Account · `account-01` — Register

**User Story 1 — Create an account**

As a new user, I want to register with my basics and default location so Decide can start near where I usually eat.

- **AC1:** Given I complete required fields (name, email, gender, default location, password, confirm password), when I submit registration, then an account is created and I can continue to profile setup. Age is optional.
- **AC2:** Given I leave a required field empty, when I submit, then registration does not complete and I see which field needs attention.
- **AC3:** Given I optionally add a profile photo, when registration succeeds, then the photo is stored with my account and the signed-in header shows a circular photo thumbnail when available.

**User Story 2 — Default location at signup**

As a new user, I want help setting default location so I do not have to type it every time.

- **AC1:** Given location detection succeeds, when the register form loads, then default location is prefilled and marked as detected.
- **AC2:** Given location detection fails, when the form loads, then I can enter location manually and see that detection failed.

---

## 9. Account · `account-02` — Sign in

**User Story 1 — Sign in with email and password**

As a returning user, I want to sign in so I can reach Decide with my saved profile.

- **AC1:** Given valid credentials, when I sign in, then I reach Decide with an authenticated session.
- **AC2:** Given invalid credentials, when I sign in, then I remain on sign-in and see that email or password is wrong.
- **AC3:** Given I forgot my password, when I follow the reset link from sign-in, then I reach the reset-password flow.

---

## 10. Account · `account-03` — Reset password

**User Story 1 — Request a reset email**

As a user who forgot my password, I want to request a reset email so I can regain access.

- **AC1:** Given an account exists for the email I enter, when I submit reset password, then the app confirms that instructions were sent (without revealing whether the email exists, if that is the security policy).
- **AC2:** Given I submit without an email, when I try to continue, then the request does not send and I am prompted for email.

---

## 11. Account · `account-04` — Set password

**User Story 1 — Set a new password from a valid link**

As a user with a valid reset or invite link, I want to set a new password so I can sign in.

- **AC1:** Given a valid set-password link, when I enter matching new passwords and submit, then my password is updated and I can sign in with the new password.
- **AC2:** Given passwords do not match, when I submit, then the password is not changed and I see a validation message.

**User Story 2 — Expired link**

As a user with an expired link, I want a clear outcome so I know to request a new reset.

- **AC1:** Given my set-password link is expired, when I open it, then I see that the link expired and how to request a new one.

---

## 12. Profile · `profile-01` — Personal information

**User Story 1 — Edit personal information**

As a signed-in user, I want to update my personal details separately from tastes so account facts stay accurate.

- **AC1:** Given I change my name or default location, when I save personal information, then the new values persist and a last-saved time is shown.
- **AC2:** Given I save personal information, when save succeeds, then a confirmation message appears and tastes are unchanged.
- **AC3:** Given I am on Profile, when I choose reset password, then I reach the reset-password flow without losing unsaved personal edits (or I am warned before navigating away).

**User Story 2 — Optional profile photo**

As a user, I want an optional profile photo so my account feels personal.

- **AC1:** Given I add or replace a photo, when I save personal information, then the new photo appears in the profile panel.

---

## 13. Profile · `profile-02` — Tastes & constraints

**User Story 1 — Save cuisine preferences**

As a signed-in user, I want to record cuisines I like and skip so Decide can match restaurants to me.

- **AC1:** Given I toggle preset cuisine chips and add a custom cuisine, when I save tastes, then my selections persist and last-saved time updates.
- **AC2:** Given I save tastes, when save succeeds, then personal information is unchanged.

**User Story 2 — Constraints and meal contexts**

As a user with dietary or situational needs, I want hard constraints and meal contexts saved so matching reflects them.

- **AC1:** Given I set spice level, party size, hard constraints, and meal contexts, when I save tastes, then those values are stored for future Decide runs.
- **AC2:** Given I leave tastes empty, when I run Decide, then the app still returns results using Decide criteria alone (with weaker or generic fit labels as appropriate).

---

## 14. Decide · `decide-01` — Search criteria

**User Story 1 — Run Decide with location and meal context**

As a signed-in user, I want to set where and when I am eating so the short list matches this meal.

- **AC1:** Given I enter area or pin, meal context, and budget per person, when I choose Find restaurants, then a new short list loads for those criteria.
- **AC2:** Given I optionally enter a craving, when I submit, then results respect that craving in matching copy or filtering where the BFF supports it.

**User Story 2 — Meal context presets and free text**

As a user, I want preset meal contexts plus free text so I can describe ad-hoc situations.

- **AC1:** Given I pick a preset from meal context suggestions, when I submit, then that context is used for this Decide run.
- **AC2:** Given I type a custom meal context, when I submit, then the custom value is accepted and shown in results context.

---

## 15. Decide · `decide-02` — Results header & summary

**User Story 1 — See when results were fetched**

As a user reviewing picks, I want to know when the list was last updated so I can judge freshness.

- **AC1:** Given a Decide run completed at 16:40 local time, when results display, then the results heading includes that last-updated time in locale-aware format.
- **AC2:** Given eight picks exist and four are shown on page 1, when the first page loads, then the summary states showing 1–4 of 8.

---

## 16. Decide · `decide-03` — Reshuffle

**User Story 1 — See other picks without changing filters**

As a user who wants variety, I want reshuffle to show the next picks from the same search.

- **AC1:** Given I have results for my current filters, when I choose Reshuffle, then the filters stay the same and a different page or slice of the short list is shown.
- **AC2:** Given I reshuffle, when new picks appear, then the last-updated time reflects whether data was refetched or reused according to product rules.

---

## 17. Decide · `decide-04` — Results pagination

**User Story 1 — Browse pages of the short list**

As a user with many picks, I want numbered pagination so I can browse without one long scroll.

- **AC1:** Given more picks exist than one page holds, when results load, then numbered page controls and Previous / Next are available.
- **AC2:** Given I am on page 1, when I choose page 2, then the next set of pick cards replaces the current page and the summary updates.
- **AC3:** Given I am on the first page, when the page loads, then Previous is unavailable; on the last page, Next is unavailable.

---

## 18. Decide · `decide-05` — Pick cards

**User Story 1 — Scan a pick at a glance**

As a user, I want each pick card to show honest place facts and how well it fits me so I can compare options quickly.

- **AC1:** Given a place has a vendor rating, when its card renders, then name, rating, category, address, and source ids (e.g. AMAP) are visible.
- **AC2:** Given the BFF computed a fit level, when the card renders, then a fit badge shows strong, partial, or weak/conflict as appropriate.
- **AC3:** Given walk time was computed from my pin, when the card renders, then walk minutes from my pin are shown; if unknown, an honest unknown label is shown.

**User Story 2 — Act on a pick from the card**

As a user, I want Details and Open map on cards so I can drill in or navigate externally.

- **AC1:** Given a pick card is shown, when I choose Details, then the place details dialog opens for that restaurant.
- **AC2:** Given a secret-free map link exists for the place, when I choose Open map, then a map opens in a new context without exposing vendor API keys.

**User Story 3 — Honest warnings on cards**

As a user, I want warnings when data is missing or travel is long so I am not misled.

- **AC1:** Given hours or price are not available from the vendor, when the card renders, then a visible note states that fact rather than inventing values.
- **AC2:** Given walk time exceeds the product threshold for this meal, when the card renders, then a long-travel warning is shown.

---

## 19. Decide · `decide-06` — Empty & partial results

**User Story 1 — Empty search**

As a user whose filters are too tight, I want an empty state with next steps so I know how to get results.

- **AC1:** Given no restaurants match my criteria, when results load, then an empty state explains nothing matched and offers to widen filters (e.g. link to Profile).

**User Story 2 — Partial vendor success**

As a user when one map vendor fails, I want partial results with explanation so I still get usable picks.

- **AC1:** Given GOOGLE_MAPS timed out but AMAP returned results, when results load, then AMAP picks are shown and a banner states which vendor was skipped and why.
- **AC2:** Given at least one vendor returned results, when partial failure occurred, then the results grid is not blank.

---

## 20. Decide · `decide-07` — List-level agent chat

**User Story 1 — Ask about the current list**

As a user on Decide, I want to chat about my current list and filters so I can refine without leaving the page.

- **AC1:** Given I have an active Decide list, when I open Chat with agent, then a panel shows the current area, meal context, and budget as chat context.
- **AC2:** Given the chat panel is open, when I send a message about filters or nearby options, then I receive a reply labeled as a suggestion (not as verified menu or hours fact).
- **AC3:** Given the chat panel is open, when I close it, then I return to the list without losing my current results until I explicitly run a new search or reshuffle.

**User Story 2 — Chat history stays on this device**

As a user, I want my list chat history kept in this browser so I can read earlier messages without storing them in my account database.

- **AC1:** Given I sent messages in list chat, when I close and reopen the chat panel on the same browser, then prior messages for this Decide context are shown from browser-local storage.
- **AC2:** Given I sent messages in list chat, when I sign in on another device or browser, then those transcripts are not available (no server-side chat history).
- **AC3:** Given I log out on this browser, when I sign in again, then list chat transcripts from the prior session are cleared from browser-local storage.

**User Story 3 — Chat is not the only search path**

As a user, I want primary search via Find restaurants so chat supplements rather than replaces structured Decide.

- **AC1:** Given I have not run Find restaurants, when I open list chat, then the app still expects a Decide run for a full short list (chat may prompt me to search first).

**User Story 4 — BFF does not persist chat**

As an operator, I want chat orchestration to stay stateless on the server so transcripts are not written to the database.

- **AC1:** Given a user sends a list-chat message, when the BFF returns a reply, then no chat transcript row is created or updated in the application database.

---

## 21. Place · `place-01` — Place details — facts

**User Story 1 — View restaurant facts in a dialog**

As a user, I want place details in a dialog so I stay on Decide or Saved while reading facts.

- **AC1:** Given I open Details from a pick card, when the dialog opens, then it shows Place details with a photo area and fact fields for name, rating, cuisine/category, address, phone, and hours.
- **AC2:** Given hours were not returned by the vendor, when the dialog opens, then hours show an honest unavailable message, not fabricated hours.
- **AC3:** Given the dialog is open, when I choose Close, press Escape, or activate the backdrop per accessibility rules, then the dialog closes and I return to the underlying page.

**User Story 2 — Freshness of place facts**

As a user, I want to know when facts were fetched so I can judge staleness.

- **AC1:** Given place facts were loaded at 16:40, when the dialog opens, then a last-updated time for place facts is shown in locale-aware format.

---

## 22. Place · `place-02` — Place details — why

**User Story 1 — Understand why this pick fits**

As a user, I want why-this-pick in the same dialog so I do not navigate to a separate page.

- **AC1:** Given I open details for a pick, when the Why this pick section loads, then bullet reasons reference my profile and current Decide context (e.g. budget band, walk time, meal context).
- **AC2:** Given other places exist in the same search list, when the dialog opens, then Also nearby lists alternative restaurants with short fit notes.
- **AC3:** Given menu and allergen data are not available, when the dialog opens, then a disclaimer tells me to confirm dishes and allergens with the restaurant.

**User Story 2 — Open an alternative from why**

As a user, I want to jump to another nearby pick from the why section so I can compare quickly.

- **AC1:** Given Also nearby lists an alternative, when I select it, then details open for that alternative (or the list focuses that pick per product navigation rules).

---

## 23. Place · `place-03` — Place-level agent chat

**User Story 1 — Ask about this restaurant**

As a user viewing details, I want place-scoped chat so follow-ups stay about this restaurant and nearby options.

- **AC1:** Given the details dialog is open, when I send a place-scoped message, then the reply is labeled as a suggestion and references the selected place context.
- **AC2:** Given list chat and place chat both exist, when I use place chat, then messages do not appear in the Decide list chat transcript (separate scopes).

**User Story 2 — Place chat history stays on this device**

As a user, I want place chat history kept in this browser so follow-ups persist while I stay on this device.

- **AC1:** Given I sent messages in place chat for St. JOHN, when I close and reopen details for the same place on the same browser, then prior place-chat messages are shown from browser-local storage.
- **AC2:** Given I sent place chat for one restaurant, when I open details for a different restaurant, then I see that place’s own transcript (or an empty transcript), not the other place’s messages.
- **AC3:** Given I sent place chat messages, when I sign in on another device, then those transcripts are not available (no server-side chat history).

**User Story 3 — BFF does not persist place chat**

As an operator, I want place-scoped chat orchestration to stay stateless on the server.

- **AC1:** Given a user sends a place-chat message, when the BFF returns a reply, then no chat transcript row is created or updated in the application database.

## 24. Place · `place-04` — Open map & save

**User Story 1 — Open map from details**

As a user who chose a restaurant, I want Open map from details so I can navigate there.

- **AC1:** Given a secret-free map deeplink exists in place sources, when I choose Open map in details, then the map opens without vendor secrets in the URL shown to me.

**User Story 2 — Save from details**

As a user, I want to save a place from details so I can find it later on Saved.

- **AC1:** Given the place is not saved, when I choose Save in details, then the place appears on my Saved list.
- **AC2:** Given the place is already saved, when details open, then Unsave is available instead of Save.

## 25. Saved · `saved-01` — Saved places list

**User Story 1 — Review saved restaurants**

As a signed-in user, I want a Saved page with the same pick-card pattern as Decide so favorites feel familiar.

- **AC1:** Given I have saved places, when I open Saved, then each saved restaurant appears as a pick card with Details and Unsave.
- **AC2:** Given I open Details from Saved, when the dialog opens, then the same place details, why, and place chat content is available as on Decide.

**User Story 2 — Empty saved list**

As a new user with no saves, I want guidance when Saved is empty.

- **AC1:** Given I have no saved places, when I open Saved, then an empty state explains how to save from a card or details and offers a path to Decide.

## 26. Saved · `saved-02` — Unsave

**User Story 1 — Remove a saved place**

As a user, I want to unsave a restaurant so my Saved list stays current.

- **AC1:** Given a place is on my Saved list, when I choose Unsave on the card, then the place is removed from Saved after confirmation or immediate action per product rules.
- **AC2:** Given I unsave from details, when I return to Saved, then that place no longer appears in the list.

## 27. History · `history-01` — Decision history

**User Story 1 — Review recent decisions**

As a signed-in user, I want recent Decide outcomes so I can remember what I chose or skipped.

- **AC1:** Given I previously marked a decision as went or skipped, when I open History, then each row shows place name, area, meal context, and went/skipped status.
- **AC2:** Given I want to eat again in the same area, when I choose Find places again on a history row, then I am taken to Decide with criteria prefilled or easily restorable per product rules.

**User Story 2 — Empty history**

As a user who has never completed Decide, I want a clear empty history state.

- **AC1:** Given I have no recorded decisions, when I open History, then an empty state invites me to run Decide once.

**User Story 3 — Reach history from Saved**

As a user browsing favorites, I want a path to History so I can switch between saved places and past decisions.

- **AC1:** Given I am on History, when the page loads, then I can navigate back to Saved from the page toolbar.
